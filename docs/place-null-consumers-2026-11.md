# 리뷰·저장수 NULL 소비처 점검 (2026-11-22, toNum NULL 전환 전 점검 · 전환은 보류)

배경: 복원 행(10/26~11/10, 123,496행)은 리뷰·저장수가 NULL 이다. toNum 을 0→NULL 로 바꾸면 앞으로도 NULL 이 생긴다.
값을 읽는 곳을 전부 찾아 **경계(10/25→10/26, 11/10→11/11)에서 가짜 증가·감소가 생기는지** 실제 화면으로 확인했다.
렌더: 실제 index.html(d1eff95)을 실제 DB 값(서울쭈꾸미쌈겹·해상공원횟집 오이도본점)으로 그림 — 로그인 대신 /api/db 응답만 바꿔 끼운 로컬 렌더.

## 지금 데이터에 '거짓 0' 이 있나 (최근 31일, toNum 의 현재 영향)
- 방문자리뷰가 양수→0 으로 떨어진 경우: **0건**. 0 인 행 4,204개는 앞뒤도 0(진짜 0 이거나 계속 빈 값).
- 블로그리뷰 양수→0: 6건, 전부 1→0, 우리 매장 아님(리뷰 삭제로 보임).
→ toNum 의 0 이 지금 화면에 가짜 ▼ 를 만들고 있지는 않다.
- 전환 전에 확인할 것 1가지: 네이버가 리뷰 0 인 가게에 "0" 을 주는지 필드를 빼는지. 빼면 전환 후 진짜 0 이 '-' 로 바뀐다. (크론 시간대 밖에 표본 1건 조회로 확인 가능)
