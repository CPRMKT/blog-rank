  - 날짜별 `place_rankings_<날짜>.jsonl.zst` 와 `.meta.json` (sha256·행 수·DB 대조 행 수)이 있다.

- **용량:** 하루 약 0.3~1.3MB, 90일 약 40~50MB 다. 월 1회 사본이면 1년 누적 약 0.5GB 이하다.

## 선택지

### A. 사장님 PC로 월 1회 복사 (권장 1단계)

- **방법:** PC가 서버에서 끌어오는 방식(pull)이다. PC에는 이미 `ssh blogrank` 접속 설정이 있다.
  - 서버에는 PC 쪽 자격증명을 하나도 두지 않는다.
  - PowerShell 한 줄: `scp -r blogrank:/var/backups/blog-rank/daily "D:\blog-rank-backup\2026-12"`
  - 원하면 Windows 작업 스케줄러에 매월 1일 등록한다.
- **비용:** 0원.
- **장점:** 서버와 완전히 다른 장소에 있다. 설정이 가장 간단하다. 새 계정이나 키가 필요 없다.
- **단점:** PC가 꺼져 있거나 사람이 잊으면 빠진다. PC 자체 고장에 대비해 외장 디스크나 OneDrive 폴더에 두면 이중화된다.
  - 단, OneDrive 는 클라우드 동기화다. 경쟁 매장 순위 데이터가 개인 클라우드로 올라가도 괜찮은지는 사장님이 정한다.

### B. 클라우드 저장소 (자동화가 필요할 때)

- **후보:** 요금은 가입 전 다시 확인해야 한다.
  - Cloudflare R2: 10GB 무료, 내려받기 요금 없음.
  - Backblaze B2: 10GB 무료, 이후 약 $6/TB·월.
  - NCP Object Storage: 서버와 같은 회사라 서버 밖 사본으로서 독립성은 낮다.
  - 이 데이터 규모(1년 0.5GB)면 R2·B2 모두 무료 범위다.
- **방법:** 서버의 백업 크론 끝에 업로드 한 단계를 붙인다.
- **서버에 두는 키의 범위:**
  - 그 버킷 하나에 **쓰기만** 되는 토큰이다. 읽기·삭제 권한은 없다.
  - 버킷에 버전 보관·삭제 잠금(객체 잠금)을 켜서, 서버가 털려도 기존 사본을 지우지 못하게 한다.
  - DB 키는 여전히 서버에 없다. 이 토큰도 지금 텔레그램 토큰과 같이 `.env`(0600)에만 두고 앞 6자리만 표시한다.
- **비용:** 0원(무료 범위). 계정 생성과 결제 수단 등록은 사장님이 직접 해야 한다.
- **장점:** 매일 자동이고 사람 손이 필요 없다.
- **단점:** 외부 계정·토큰이 하나 늘어 관리 대상이 된다.

### C. cpr-marketing-os 쪽 보관 (비권장)

- 그 저장소는 같은 PC에 있다. 그래서 장소 분산 효과는 A와 같다.
- git 저장소에 넣으면 문제가 둘 있다.
  - 바이너리가 매달 쌓여 저장소가 커진다.
  - GitHub 로 push 되는 순간 순위 데이터가 제3자 저장소에 올라간다.
- 쓰려면 git 밖의 일반 폴더에 두는 수밖에 없고, 그러면 A와 같다.

## 복구 시험 절차 (월 1회, 사본을 받은 직후)

1. **고르기:** 사본에서 날짜 3개를 무작위로 고른다. 최근·한 달 전·가장 오래된 것.
2. **해시 확인:** `sha256sum` 결과가 `.meta.json` 의 `sha256` 과 같은지 본다.
3. **행 수 확인:** `zstd -d` 로 풀고 줄 수가 `rows` 와 같은지 본다.
4. **DB 대조:** 같은 날짜의 DB 행 수와 비교한다. 무작위 20행을 id로 찾아 순위·이름·리뷰 수가 같은지 본다. 읽기 조회만 한다.
5. **복원 연습(분기 1회):** 운영 DB가 아닌 곳에 하루치를 넣어 집계가 같은지 본다. 운영 DB에는 쓰지 않는다.
   - 넣을 곳: Supabase 브랜치(유료 기능, 사용 전 비용 확인), 또는 PC의 임시 Postgres.
6. **기록:** 결과를 `docs/ops-*/backup-restore-test-<날짜>.md` 에 한 줄씩 남긴다.
