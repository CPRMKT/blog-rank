# Supabase 프로젝트 이전 — 기준값과 점검 (2026-11)

## 왜 옮기는가
blog-rank 의 Supabase 프로젝트(이름 `blog_rank`)는 무료 조직 **CPRMKT** 에 있고,
DB 695MB(사용량 화면 744MB)로 무료 한도 500MB 를 넘어 **EXCEEDING USAGE LIMITS** 상태다.
계속 넘기면 조직 단위로 402 가 걸려 수집과 화면이 함께 멈출 수 있다.
대표가 직접 대시보드에서 이미 유료(Pro)인 조직으로 옮긴다.
**이 저장소 쪽에서는 대시보드 조작·결제·요금제 변경을 하지 않는다.**

## A-3. 이전으로 바뀔 수 있는 값이 쓰이는 곳 (이름·위치만)
조직 이전은 보통 **프로젝트 ref·URL·키가 그대로 유지**된다(프로젝트를 다시 만드는 게 아니다).
그래도 바뀐다면 고쳐야 할 곳은 아래뿐이다.

| 위치 | 이름 | 비고 |
|---|---|---|
| Vercel 환경변수 | `SUPABASE_URL` | 프로젝트 URL |
| Vercel 환경변수 | `SUPABASE_ANON_KEY` | 화면·로그인용 |
| Vercel 환경변수 | `SUPABASE_SECRET_KEY` | service_role |
| cpr-marketing-os 쪽 | DB 연결 문자열(`cprmkt_readonly_sync` 계정) | 이 저장소 밖 |

**NCP 스크래퍼(`/opt/blog-rank/scraper/.env`)에는 Supabase 값이 하나도 없다** —
`SCRAPER_API_KEY`, `PORT`, `CRON_SECRET` 뿐이고, DB 는 전부 Vercel(`/api/db`)을 거친다.
그래서 이전 때 **서버는 손댈 것이 없다.**
로컬 저장소에도 `.env` 파일이 없다(값은 전부 Vercel 에 있다).
